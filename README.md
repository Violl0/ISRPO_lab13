## Практическая работа №5. Список у ворот

1. Кто теперь проверяет повтор при добавлении и почему не Program? Повтор проверяет Guild в AddHero, потому что правило должно работать везде, а не только там, где о нём вспомнили.
2. Когда FindHeroByName возвращает null? Когда героя с таким именем нет в составе или запрос пустой.
3. Зачем очищать запрос, если имена героев уже очищены? Чтобы запрос " аРтЁм " нашёл "Артём" - пробелы по краям мешают сравнению.
4. Почему MemberCount не хранит число, а вычисляет его? Потому что при каждом чтении берёт актуальный _heroes.Count, второй счётчик не нужен.
5. Удаление из гильдии уничтожает героя? Нет, убирает только из состава, объект остаётся.
6. Почему private-поле не защищено, если вернуть его из метода? private закрывает имя поля, но не объект - если отдать ссылку наружу, можно вызвать Clear.

Трассировка: прогноз True, False, True, True, 1, 2, True - совпало.

Ошибка 1: return null внутри цикла завершал метод после первого несовпадения.

Ошибка 2: возвращался сам _heroes, а не новый список с теми же ссылками.

Самостоятельный шаг: FindStrongest возвращает Hero?, потому что героя может не быть, а CountHealthy всегда может вернуть число. При null вызывающий проверяет и не лезет в свойства.

### Личный проект

Ключ: название книги, потому что в каталоге магазина книга уникальна по названию.

Когда подведёт: два разных издания с одинаковым названием.

Обработка null: поиск возвращает null, Program проверяет и выводит, что книги нет.
